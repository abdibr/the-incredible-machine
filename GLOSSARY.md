# Glossary — The Incredible Machine (web clone)

Single-context domain vocabulary. Architecture decisions live in `docs/adr/`; the generated interaction reference is `docs/interactions.md`. Keep entries short; this file is the term index for the whole codebase.

## Objects & bodies

- **Object (game object)** — one interactive thing in the puzzle; a `BaseObject` subclass instance with a stable `type` string (e.g. `'rope'`, `'scissors'`). Lives in `js/objects/`.
- **Body** — a Matter.js rigid body owned by an object; an object may own several (e.g. Scissors: two blade sensors + two solid handles).
- **Body label** — the Matter body's string `label` (e.g. `'candle-flame'`, `'scissors-blade'`, `'bucket-sensor'`). Labels are unique per object family and are the fine-grained discriminator between an object's bodies.
- **Sensor body** — a Matter body with `isSensor: true`: reports collisions, exerts no physical force (candle flame, scissors blades, bucket catch zone).
- **Boundary walls** — the four static playfield walls (`wall-floor/left/right/ceiling`) created inside `PhysicsEngine`. They are *not mapped to objects*, so they never enter interaction dispatch — documented null-participants (ADR 0001 decision 6). Objects cannot react to wall contacts; the deliberate wall consumers outside the matrix are Mouse's static-body probes and `GoalChecker`'s off-world (tunneling → `goal:failed`) check.
- **Custom id** — a named id from level JSON (`"id": "bucket-goal"`), separate from the auto-increment instance `id` used for snapshots/dedup.

## Interaction matrix

- **Interaction matrix** — `js/interactions/` (`InteractionMatrix.js` + `rules.js`): the single registry of object-to-object reactions; `PhysicsEngine` feeds `collisionStart` pairs into `resolve()`.
- **Row** — one declaration in `rules.js`: `{ id, summary, actor, target, handler, test }`. The row is the unit of documentation and testing.
- **Actor / target** — the reacting object / its counterpart. Handlers receive them in canonical `(actor, target)` order.
- **Matcher** — a row side's accept condition: `{ type, label?, predicate? }`; an empty matcher is a wildcard. `type` keys on the object type string; `label` requires the collision pair to contain that labeled body; `predicate` delegates to a decision method on the object.
- **Handler** — `(actor, target, pair) => void`; routes to the actor's public behavior method. Behavior itself stays on the object.
- **Decision method** — object-owned, state-dependent accept check used by predicate matchers (`Bucket.isCatchContact`, `Scissors.isSnapTrigger`, `Mouse.isRelevantContact`, `Spring.isLaunchTrigger`). Pure: no state changes.
- **Behavior method** — object-owned action invoked by handlers (`rope.sever()`, `balloon.pop()`, `bucket.registerCatch()`, `gear.meshWith()`, `scissors.snapShut()`, `mouse.reverseFromContact()`, `spring.armLaunch()`, `trampoline.stretch()`).
- **Canonical orientation** — rows are unordered pairs; `resolve` tries both orientations so dispatch order never matters.
- **docOnly row** — a row with `docOnly: true` that never dispatches; documents deliberate empty cells (boundary walls, silent classes).
- **Silent class** — an object class that declares no reaction rows (Ball, Ramp, Conveyor, Fan, Domino, Pulley, Candle): contacts affect *other* objects, never them.
- **collisionStart pair** — one Matter contact event between two bodies; the only dispatch point the matrix covers. Persistent/geometry interactions (conveyor surface, fan wind) legitimately live in `onBeforeUpdate`.

## Engine & lifecycle (history)

- **onCollision hook** — the pre-matrix per-object collision hook; *removed* 2026-10-18 (ADR 0001). Do not reintroduce; add a row instead.
- **Snapshot / restoreState** — play/reset determinism seam: `PhysicsEngine.takeSnapshot/restoreSnapshot` restores bodies; objects with behavioral state re-apply it via `restoreState` (Mouse, Pulley, Scissors).
- **Event bus** — `js/EventBus.js` decoupled events (`rope:severed`, `balloon:popped`, `bucket:caught`, level flow). PhysicsEngine consumes severing/removal; GoalChecker consumes catches.

## Discovery & wake (ADR 0002)

- **Discovery seam** — the only way game objects scan the world: `PhysicsEngine.queryTouching()` (SAT-precision contacts), `queryZone()` (position-in-local-rect), `queryPoint()` (vertex-precise point probe). Objects never call Matter query APIs directly.
- **Wake-on-act** — an object wakes (`wakeBodies()`) exactly the bodies it acts on, right before applying a force/constraint: asleep bodies skip force integration in Matter, so acting without waking silently does nothing.
- **Discovery never wakes** — the query methods are pure reads; sleeping candidates come back asleep. Sleep state has a single writer: `wakeBodies()`.
- **Movable-non-wall-non-own policy** — default discovery matches dynamic bodies only; boundary walls (`wall-*` labels) and statics are opt-ins per call (`includeWalls` / `includeStatic`), and a caller never discovers its own bodies.
- **Object-level query** — `queryObjectsByType(type)` / `queryObjectsByBodyLabel(label)` (ADR 0002 amendment): discovery returning registered game objects instead of raw bodies, filtered by `type` or by owning a labeled body; a pure read over the registry, with opt-in self-exclusion (`excludeOwner`).
- **Overlap zone** — `queryZoneOverlap(referenceBody, zone)` (ADR 0002 amendment): zone matching by bounds intersection instead of centre-inside, so large bodies whose centre is outside a narrow zone are still discovered; ordering/policy/shape identical to `queryZone`.
- **Impulse field** — `applyImpulseField(sourceBody, {zone, range, force, direction?, match?})` (ADR 0002 amendment): the engine's shared directional-force law — source-local rect zone (position-inside or bounds match), linear distance falloff from the source centre, mass-scaled force along a source-local direction (default "up"), wake-on-act in the same call. Fan wind is the first consumer.

## Lifecycle & restore (ADR 0003)

- **Lifecycle contract** — every object goes create → play (`onBeforeUpdate` per step) → restore (`restoreState` across a play/reset cycle) → dispose; optional seams (`onBeforeUpdate`, `restoreState`) are default no-ops on `BaseObject`. A new object type must satisfy the conformance sweep in `tests/object-contract.test.js`.
- **restoreState** — the snapshot-restore seam: `PhysicsEngine.restoreSnapshot()` re-apposes bodies by body id, then calls `restoreState` on body-id-matched objects for behavioral state only (never positions). Transient state resets "cycles start clean" (Bucket catches, Spring trigger, Trampoline stretch, Mouse cooldowns); Gear is snapshot-faithful (drive from the serialize ride-along).
- **Dual restore paths** — *physics restore* (`GameLoop.reset()`): same instances, body-id matched, `restoreState` seam. *Placed restore* (`js/reset/levelReset.js`): fresh deserialize from the placed snapshot — construction IS the restore, new ids.
- **loadCustom** — the only seam for ad-hoc level data (editor JSON import): installs `LevelManager._currentLevel` and emits `level:loaded` exactly like `loadLevel(id)`; UI never emits `level:loaded` directly.
## Runtime constraint links (ADR 0004)

- **Constraint link** — a Matter constraint created and managed by `PhysicsEngine` (`attachConstraint`/`detachConstraint`/`getAttachedConstraints`) between two registered objects' bodies; individually detachable at runtime.
- **Object-owned constraint** — a constraint a game object builds for its own structure (rope segment chains); never registered by the engine, not detachable through the link seam, removed wholesale with its object.
- **Co-termination** — the engine policy that removing an object detaches every link endpoined at its bodies: an orphaned endpoint would drag the survivor toward a dead body forever.
- **Link record** — the plain-data capture of a link's effective parameters (body ids, anchor points, stiffness, damping, length) that rides the snapshot seam (ADR 0003).

## Rope connector (ADR 0005)

> Connection UX is being redesigned (ADR 0007, `docs/adr/0007-rope-connection-redesign.md`): explicit click-to-connect replaces all proximity tying; a rope ties through exactly three named seats — anchor, mid, end — one knot per seat, three knots per rope (the any-segment generalization this note once carried is retired, see **Segment tie point** and the ADR's 2026-11-22 amendment); and a `free-rope` toolbox type joins `rope` — see **Rope redesign (ADR 0007)** below. The engine seams (link realization, token round-trip) stand.

- **Endpoint (rope)** — one of a rope's two end seats: the **anchor seat** (the nail a pinned rope hangs from; the spawned free chain's first body, which moves with it) and the **end seat** (the free-chain last segment's body; no end anchor body exists). Tied with `attachEndpoint` through the seat ROLE, never an index (the 0|1 endpoint spelling here is pre-#90 history); re-laid wholesale with `setEndpoints` (edit-time only). (ADR 0007 amendments: tying no longer generalizes to any segment's tie point — the endpoints ARE the rope's two end seats themselves, and mid-chain knots ride the mid seat; see **Seat (tie seat)**.)
- **Attachment point** — a named, body-borne tying spot an object offers: `attachmentPoints` → `{ id, body, offset }`, world position via `getAttachmentWorldPoint(id)` — body-local resolution (issue #100): the offset rides the point's own body's angle (`position + rotate(offset, body.angle)`), so every reader — tie square, knot ring, knot tooltip, drawn knot, the reconcile's links — answers the point the realized engine link pins at any body angle (the unrotated `position + offset` spelling ADR 0005 decision 7 first recorded held only while every attachment-bearing object rendered upright — amended in place there and recorded in ADR 0007's 2026-11-21 amendment). Contract on `BaseObject` (default none); Balloon offers `knot` (gone when popped), Bucket offers `rim`. (ADR 0007: offered points render as clickable target squares in the connect flow, shown when relevant.)
- **Knot** — one live rope-side tie, riding one of the rope's three named seats by ROLE — the live ref is `{ seat, target, pointId }`: one knot per seat (issue #85), at most three knots per rope; a seat that already holds its knot refuses a second tie. One attachment point still serves every rope that ties it (a target's capacity is per point, seat capacity is per rope). Live refs only — tokens never live in runtime state. (ADR 0007's three-seat amendments supersede both the per-endpoint form and the any-segment generalization this entry once recorded.)
- **Knot reconcile** — the per-step convergence in `Rope.onBeforeUpdate`: realize missing knots as length-0, stiffness-0.9 engine links (offset as `pointB`), drop engine links that no longer match a knot, prune refs whose target popped/disposed/no longer registered. A severed rope realizes nothing. (ADR 0007 supersedes the severed case: piece severing has the surviving pieces realize the knots of their own segments.)
- **Seat token (the knot token)** — a knot's serialized form — one per occupied seat, at most three per rope — written only by the board annotator `levelReset.serializePlacedBoard` (rope rows may carry `attachments`; `Rope.serialize()` never emits knots): `{ seat: 'anchor'|'mid'|'end', targetType, targetOrdinal, pointId }` — the seat ROLE carried straight from the rope's own role-keyed refs (the role schema was introduced in issue #88; issue #90 deleted the index beneath it, and ADR 0007's 2026-11-22 amendment retires the decision-6 segment schema this schema answers), and restoring binds each knot at the same seat of the restored chain whatever that chain's count (a mid token onto the 12-chain is the 12-chain's middle). `targetOrdinal` indexes the full board snapshot array (fixed objects first, placed parts after — stable order); same two-phase bind. Pre-#90 numeric tokens (`segment` issue #56, `endpoint` issue 04) do NOT load: each refuses at bind with a clear warning and that knot drops (re-tie the board); nothing throws.
- **Two-phase bind** — `restorePlacedFromSnapshot` deserializes *every* row first, then ropes resolve their tokens against the rebuilt board (`bindAttachment`); board/row count disagreement binds nothing (warned); unresolvable tokens drop (warned); a severed rope binds nothing.
- **Weld constraint** — a stiffness-1 distance constraint an object builds to hold its own dynamic parts in shape (Bucket: wall↔wall↔floor triangle + sensor pinned to floor); object-owned, exposed via `constraints`, skipped entirely when the object is fixed. Enables welded-movable containers without compound bodies (collision dispatch stays part-body keyed).
- **`rope:chain-converge`** — event from `Rope.restoreState` when a rewind revives a severed live rope to an intact snapshot: the rebuilding rope announces `{ rope, previous }` and the engine consumer (`_restoreRopeConstraints`) re-adds the rebuilt chain to its world (bus-global; guarded per engine).
- **Snap hint** — drag-time placement feedback while a tool-ghost rope hangs on the cursor: the renderer marks every board attachment point — faint dashed marker beyond reach, bright marker + tie-line when a clamped drop would tie. Gated by `ROPE_SNAP_RADIUS` (exported from `Rope.js`, shared with the DragDropManager placement snap) and suppressed in play modes. (ADR 0007: superseded — proximity tying and all snap/attract hints are removed in favor of the explicit connect flow.)

## Rope redesign (ADR 0007)

Decided in `docs/adr/0007-rope-connection-redesign.md` (the record the design grilling settled), built across the fork's rope-redesign ticket set: the connect flow, the free-rope bundle (issue #55) and span-derived counts with knots on the three named seats (issue #56; role-addressed since #90) are live; **rope-to-rope knots (issue #57)** and **piece severing (decision 7, issue #58)** are live; routing remains future. New terms:

- **Rope family** — the rope-module membership fact (C1, issue #75, ADR 0007 decision 1): the type keys that tie, cut, burn, record knots and are anchor-refused as ropes — `Rope.ROPE_FAMILY_TYPES` plus the `isRopeFamilyType`/`isRopeFamily` predicates in `Rope.js`; today `'rope'` and `'free-rope'`. Every gate site that asks family membership asks the module's fact instead of a hand-rolled string pair, so a new member is one append (plus its registry prose) and a conformance alarm (`tests/rope-family.test.js`) fails loudly when a `Rope`-derived registry type skips the list. The whole-roster consumers ask the one seam, `Rope.queryRopeFamily(engine, opts)` (issue #83) — one query over the `ROPE_FAMILY_TYPES` members through the engine's own `queryObjectsByType`, `opts` forwarded; membership stays in the rope module and `PhysicsEngine` stays untouched (ADR 0002) — Scissors's cut scan through the seam, `agent/observe/state.js`'s extras through the `isRopeFamily` predicate, so a third member is one append there too. The three knot-walking consumers (bug-file narrator, knot renderer, placed-board token annotator) deliberately gate capability-first — "offers attachment refs" — not on this list, so a family member narrates, renders and annotates knots by the same rule.

- **Rope as a tie target (issue #57)** — the rope-as-target half of decision 6: a rope's ENDPOINT BODIES are attachment points — `Rope.attachmentPoints` answers `anchor` (the nail, or a spawned chain's moving knot) and `end` (the tail), offset 0 (the body centers), named by the seat roles the bodies bear; a bodyless bundle answers none (its coil square is a seek entry only) and a disposed rope nothing. So a seek from any square can click a rope's square and knot rope-to-rope; mid seats keep their seat squares but are NOT tie targets (the acceptance scope is the endpoint squares). The target side keeps the attachment-point rule — one point serves every rope that ties it; the one-knot-per-seat gate stays the seeking rope's. The knot realizes through the same reconcile as every tie (each rope's desired set also names the INBOUND pairs the other ropes' refs tie into its points — the scan that drops a rope's own stale links must not kill what another rope's ref claims at its bodies), and restores through the same seated ordinal token (`pointId` is the target rope's seat role). Rope targets are exempt from the anchor-seat tie pull (a rope endpoint is structure — no nail relocation; the residual gap settles at play like an immovable target's).
- **Severed-target refusal (issue #57)** — the pre-piece-severing policy from the tie side: a severed rope holds no knots from either side. `attachEndpoint` refuses a severed rope-family target (a restore token drops with its warning), the connect flow offers no target squares for one, and the reconcile PRUNES into-knots whose target is severed — the sever consumer co-terminates the engine links, the prune kills the refs that would re-realize them, so nothing dangles. Rewinds do not resurrect (the same accepted shape as the popped-balloon prune).
- **Piece** — one surviving connected component of a cut chain (`Rope.getPieces()`, issue #58, ADR 0007 decision 7): DERIVED, never stored — the chain's bodies between consecutive cut edges, in chain order, the anchor joining the anchor-side piece. An intact rope answers one piece; a bodyless free bundle and the record-less legacy severed shape answer none. Each piece keeps the knots attached to its own segments and realizes them in play (the engine's sever consumer keeps exactly the links the pieces keep), while the cut rope itself still holds no knots from either side — the severed-target refusal above stands. A cut persists only `_cuts` (the dead chain-edge indices, serialized on the row); pieces re-derive from them on restore and never ride a row.
- **Beat** — one play step as a rope counts it (`Rope.onBeforeUpdate` bumps `_tick`): the cut-coalescing unit (issue #58). One cut per beat — the several collision pairs one wide overlap band produces in a single physics dispatch land as ONE cut (the first hit wins its boundary edge, from `_cutEdgeFor`); a hit whose boundary edge is already dead is absorbed on any beat (repeats at a cut location change nothing). A rope that has taken no step yet holds no beat record, so a pre-first-step cut lands without coalescing.
- **Bind-order deferral (issue #57)** — the two-phase bind's rope-to-rope retry: a token whose TARGET rope has laid no chain at bind time (the spawned free rope that births during ITS own anchor token's pass, issue #55) defers in `_pendingAttachments` instead of dropping; `restorePlacedFromSnapshot` and the replay board builder drive the passes through `bindPlacedTokens` while tokens keep landing, then one strict pass drops leftovers with warnings — nothing stays pending. A plain `bindAttachment(board)` call is strict exactly as before.

- **Connect flow** — the explicit click-to-connect interaction replacing ALL proximity tying: rope tie seats render square handles (issue #85: exactly the three named seats — anchor, mid, end — plus a bodyless bundle's single coil square; never one per chain body, so a fourth knot is unreachable), attachment-bearing objects render target squares when relevant; clicking a free rope square seeks (preview line follows the cursor, valid targets glow), clicking a glowing target ties — and, on a free rope, the flow stays armed on the NEXT FREE seat: it advances anchor, then mid, then end, re-reading `getTieSeats()` for wherever the live count puts the mid, and closes when no seat after the tie is free (issue #103; the pinned family's tie still ends the seek). A tied seat always paints gold, so an armed preview never aims an occupied seat. Esc / re-click cancels, clicking a tied square unties exactly that seat's knot (target stays) and a tie aim into an occupied seat refuses without creating a knot — one knot per seat, three per rope. Lives in its own module that the drag-drop handler delegates to; the renderer draws squares, preview, glow. Edit-only — hidden in PLAY, in-flight seek cancelled at the last settled state on stage change.
- **Bundle** — the free rope's inert pre-tie form: a static coiled graphic with exactly one square entry point and no physics bodies (doesn't fall, can't be cut in play); selectable/movable via drawn bounds. First tie unrolls it into a chain hanging from the tie point (which then squares its three seats, #85); untying its only knot re-bundles it; deleting an untied bundle removes just the graphic + row.
- **Segment tie point** — RETIRED (issue #90): the per-segment addressing ADR 0007 decision 6 introduced (a knot token's `segment` index, generalizing the old `endpoint` 0|1). A rope answers exactly three tie seats and ties through them by role — mid-chain knots stay first-class through the mid/end seats; the segment-index API, its schema range (`Rope.validSegment`) and the numeric token forms are gone (a legacy token refuses at load with a warning).
- **Seat (tie seat)** — one of exactly three tie slots a rope answers — two ends and one mid — each named by its ROLE and nothing else (issues #84/#85; the index addressing is retired, issue #90). The **anchor** seat is the pin/nail square of a pinned rope (the spawned free chain's first body — ADR 0007 decision 5's mobile knot — or the coil square of a bodyless bundle); the **mid** seat is a ROLE over the live chain, not a body — the middle of whatever count the chain holds (`midSeatSegment(count)`: exact for odd counts, tied anchor-ward on even ones), resolved per ask and never stored; the **end** seat is whatever body the chain tail currently is. The roles are the ONLY seat names: `Rope.attachEndpoint`/`Rope.detachEndpoint` take `'anchor' | 'mid' | 'end'`, an unknown name is refused with a clear error, and no public rope API accepts or returns a chain index as a seat. One knot per seat (issue #85): a seat that already holds a knot refuses a second tie — no knot is created, no token may stack two knots on one seat — so a rope tied through its squares holds at most three knots, while untie stays per-knot (a tied square's click unties exactly that seat's knot, the target kept). `seatFraction(seat, count)` = where the seat's tie body sits along the span, by role — the one spelling of the seat arithmetic shared by the per-seat reach gate (issue #86: a seat's tie aim gates on its own fraction, past the aim tolerance refusing — the anchor seat keeps the whole-rope capacity circle since its knot consumes no chain), the tie-grow's covering rule and the hand's inverse. Because mid and end are roles over the live chain, a re-count trades no binding: the mid knot rides the new middle, the end knot the new tail, the anchor knot the anchor (issue #87's keeps, carried by the roles since #90 — nothing re-seats), and the reconcile realizes each knot's link from whatever body its seat then names.
- **Named seats (anchor, mid, end)** — the three tie seats a rope ANSWERS by name, `Rope.getTieSeats()` (issue #84): each seat's `role` (THE seat address since #90 — the way attach/detach, live refs, tokens and squares all speak), its tie body, its world point at ask time, and its reach fraction (`seatFraction`; the anchor seat 0, the end seat the covering limit). The **mid seat** is a role on the live chain — the middle body, exact for odd counts, tied anchor-ward on even ones — resolved per ask and never stored, so a re-lay or tie-grow (either family) keeps it the middle with nothing written at tie time. Presence follows the live structure: a laid rope answers three, a bodyless free bundle only its coil anchor seat (no body, the coil point), a disposed rope nothing. The connect flow squares exactly these seats (#85): three on a laid rope however long the span, the coil seat on a bodyless bundle until its first tie spawns the chain.
- **Span-derived count** — `Rope.segmentsForSpan(span)`: a chain's segment count as a function of its span (≈40 px pitch, `SEGMENT_DENSITY_PX`), floored at `SEGMENTS` (6 — the classic fresh drop every short span keeps) and capped at `MAX_SEGMENTS` (16, so huge spans stretch instead of exploding the body count); invalid spans (0, negative, NaN, Infinity) answer the floor. It is *the* count rule at every seam: birth (ctor/`_layChainFrom`), re-lay (`setEndpoints`), the tie-grow's covering re-lay (`attachEndpoint`), the hand (`relayFreeEnd`) and the restore— one rule since issue #89.
- **Tie-grow** — the reach adjustment a tie makes (`Rope.attachEndpoint`) — the ONE way a tie may change the rope's length, and only upward: a tie never shortens the rope, and it grows only through its own seat's fraction. It fires when the aim passes the tied seat's covering circle (`tied > length x seatFraction(seat, count)`) and re-lays the chain along the tie direction through the two-pass seal (issue #99): `span1 = tied / frac(seat, count0)` names `count1 = segmentsForSpan(span1)`, the chain re-lays for the span the post-count fraction answers (`tied / frac(seat, count1)`) — so the seat lands ON the knot, a band-crossing grow does not overshoot past the knot, and the appended tail sits on the cursor the frame it grows. The count re-derives from the grown span like every other lay — one covering rule for both families (issue #89; the frozen-count exception this entry once carried is retired, and the seats keep every knot on its role, issues #87/#90). Narrow case of a re-lay, and the one that must not be confused with it.
- **Re-lay** — laying the chain again end-to-end (`Rope.setEndpoints`): the count re-derives from the span — ONE mode (issue #89 retired the frozen variant), so a genuine re-lay, a tie-grow's covering re-lay and a re-root re-count the same way — the tail trades (append/drop — earlier seats keep their bodies, so live knot refs stay valid) and the `rope:chain-converge` packet carries `{ added, dropped }` for the world swap. A re-root re-lays over the span it already has, so its packet trades nothing unless band-edge float dust flips a count; a tie-grow is the narrow case; a re-lay the general one.
- **Authored span** — `Rope.hasExplicitSpan`: whether a rope's length came from its author (a level row, the hand, a test) rather than the bodyless-coil default. Recorded once in the ctor and only ever read, because a supplied `100` and a defaulted `100` are the same number. For a free rope it is the **chain-vs-coil** discriminator: an authored free rope lays its chain as it enters a world (`birthAuthoredChain` from `PhysicsEngine.addObject`), while a length-less one stays issue #55's inert coil until its first tie. Restore carries it separately as `options.authoredSpan` — defaulted from the row's `spawned` discriminator — because `serialize` always writes `length`. The token-bind birth of a restored spawned rope consults it too (issue #93, the ADR 0006 amendment): the chain lays along the row's saved span direction — the restore lay — with the straight-down birth left to a fresh live coil.
- **Persisted chain count (`options.segments`)** — RETIRED (issue #89): the laid segment count used to ride a rope's row beside `length` (issue #56) and a restore birthed it instead of re-deriving — that kept a pinned rope's frozen-count tie-grow from re-firing per save → load → save. With the one covering rule the count is a pure function of the span at every seam (birth, re-lay, tie-grow, restore), so the cycle is idempotent by arithmetic and no row carries a chain count; a pre-#89 row's stale `segments` key is ignored. Do not reintroduce — the row's `length` plus `segmentsForSpan` answer.
- **Length freeze** — `Rope.lengthFrozen`: a rope's length is the hand's while untied and frozen after its first tie, re-orientable afterwards only around the reach circle (decision 4). Derived from the knot list (never stored, so it cannot drift); the *free* family keeps its span the hand's regardless (its re-lay takes any demand), which is why the getter reads knots while only pinned ropes behave frozen.
- **Sheave** — future-routing vocabulary: a grooved guide the rope's path bends over. Routing (a separate router object, future ADR) is a deterministic geometric rule rendered visibly — never serialized as a knot token, re-derived from geometry on restore. Pulleys expose no attachment squares; routed ropes sever whole-rope (overrides piece severing).

## Bug files (ADR 0006)

- **Bug file** — the exported JSON record of one sandbox visit: header (`schemaVersion`, `fileId`, engine facts, notes) + `build[]` + `runs[]`. Downloads as `bugfile-<fileId>.json` from the Editor panel; working copies live in gitignored `.scratch/bugfiles/`; graduated files live **verbatim** in `tests/fixtures/bugfiles/` and are replayed by the suite as regressions.
- **Session recorder** — `js/recorder/SessionRecorder.js` (DOM-free core + `browser.js` shims): always-on in SANDBOX; arms on `MENU → SANDBOX`, disarms when the visit leaves the sandbox family; the crash mirror makes sessions recoverable after a reload.
- **Build trace** — the `build[]` edit-event narrative with per-action object snapshots (rope knots as narrative tokens, ref `type#<instanceId>`); diagnostic only — never re-executed.
- **Run** — one play cycle inside a session: play-start **board snapshot** (the authoritative replay source) + the raw recorded dt stream + normalized events + sampled poses (every 6th tick default, dense = every tick, rolling budget, `endedBy` marker). Runs open on `loop:play` while stopped; pause/resume stays inside the run.
- **Run-lifecycle owner** - the GameLoop seam, the ONE place run ordering lives (issue #77): the loop publishes the run facts as they happen - `loop:play` (begin), `loop:frame` per physics step (step-to), `loop:reset` the end fact (restored in #76), `loop:pause` a within-run fact - and `reset()` is the owned, idempotent run-stop. The recorder consumes the published facts (it keeps the run state, not a loop-state copy), and the overlay paths call the owned stop instead of hand-deriving `isStopped` guards; the agent session and the replay harness consume the same published facts (issue #78) - trials framed with `loop:play` -> per-step `loop:frame` -> `loop:reset`, replayed runs closed by the published end fact - and answer to the owners of what they used to re-derive (the level schema via `LevelManager.validateCustom`/`loadCustom`, snapshot rebuilds via `restorePlacedFromSnapshot`).
- **RefId** — the cross-session stable object reference: a board row's `customId` when it has one, else `type@<boardOrdinal>` (board order is what `serializePlacedBoard` annotates against). Matter body ids never leave a session.
- **Divergence report** — the harness's first record-vs-replay mismatch over the *replayable* topics (physics verdicts + canonical-ordered collision pairs) plus pose rows compared by tick; `node scripts/replay-bugfile.mjs <file>` prints it and exits 1 on any divergence.
- **`physics:collision`** — the recorder file's collision row, captured by the recorder's own `Matter.Events` hook with canonical pair ordering (Matter's a/b orientation is emergent, not stable across sessions). NOT a bus topic — bus dispatch stays matrix-only (ADR 0001).
- **Events-only mirror** — the ~2 s throttled `localStorage` projection (header + notes + build + run events + dt stream, never poses) from which a crashed/reloaded session is recoverable and exportable.

## Goals & editor (issues #11, #63, #66, #67, #68)

- **Goal zone** — the object (a bucket) whose named id equals `goal.zoneId`; `GoalChecker` wins on it via `bucket:caught`. Resolved by one shared helper, `resolveGoalZoneObject`, so the editor readout, the renderer and Save can never disagree about which object it is.
- **Goal-zone marker** — the dashed frame + "GOAL" caption the renderer draws around the goal zone in edit modes only. Live-view semantics: a loaded level marks only its own `goal.zoneId` object (nothing if that zone is gone); a goal-less sandbox (#63) marks the unnamed fixed bucket the next Save would stamp.
- **Goal readout** — the Editor panel's plain-language goal status: the live session line (goal-less until Load Level; warns when a loaded zone matches nothing) and the next-save line ("Save Level will use…", sandbox stamp-fallback semantics). Refreshed on enter, select change, level load and board changes.
- **Stamp fallback** — the sandbox rule for a zone without an explicit match: the FIRST unnamed fixed bucket, exactly the one `stampGoalZoneIds` names `bucket-goal` on Save. A "save view" (readout save-line) uses it; a "live view" (readout live-line, marker on loaded levels) never does.
- **Selection handle set** — which selection affordances a part offers, and which move/rotate/delete verbs are accepted: one state-driven policy in `js/ui/selectionHandles.js` (part state × stage posture, issues #68/#67; the scene-lock row from ADR 0009). The renderer derives both what it draws and what it hit-tests from it; the DragDropManager gates its verbs with the same rows — offering, drawing, hit-testing and interacting can never disagree. The anchored part (#67) is one such row.
- **Sandbox authoring** — the SANDBOX posture that edits scenery in place: pinned, anchored and scene parts keep their full handle set there (dragging a pinned goal bucket IS the #66 goal-zone authoring move). Every other stage leaves a player-authored pinned part only its pin, a player-authored anchored part only its anchor — the unpin/un-anchor escape hatches for the player's OWN states — while authored scene parts (ADR 0009, see Scene content) offer nothing at all.
- **Scene content (isScene)** — authored board furniture from level `fixedObjects`: every row rebuilt through the level seams (`levelObjectOptions`) is stamped `isScene` (a BaseObject lifecycle flag riding serialize/restore like the pin flags). Solving a level may neither rearrange nor un-author its contents: scene parts offer NO selection handles in the player postures — no move, no delete, and crucially no un-pin/un-anchor route into a movable part (the level-06 target ball could be un-anchored and dragged straight into the bucket). The sandbox keeps the full affordances for authoring. Classification beats the pin flags: a scene part is scene whether pinned, anchored or dynamic (ADR 0009).
- **Anchored part** — a part state (issue #67) beside pinned scenery: placed by the author in the sandbox (⚓ selection handle or A key), refused to the player in the edit stage (selection works; move/rotate/delete never start), yet physically dynamic at play — gravity applies, it can fall, roll, be hit and be caught. Anchoring never statics bodies (that distinction is the whole point); the states are mutually exclusive through the BaseObject accessors (pinning absorbs the anchor, anchoring un-pins). Rows carry the `isAnchored` marker through serialize/save inside `fixedObjects`, and the rebuild-row rule (`levelObjectOptions`) honors it in every board reload/rewind. Rope/free-rope are out of scope until the connector redesign. An anchored bucket cannot be the goal zone — goal zones are pinned buckets. (ADR 0009: the un-anchor escape hatch now exists only for player-authored anchored parts; an author's anchored scene row is locked shut — see Scene content.)
- **Solution scene** — the solved board a level ships as its solvability proof: `solution.scene` in level JSON, in the placed-snapshot row shape (fixed rows + placed rows, rope knots as attachment tokens). Every campaign level carries one; the campaign loader and player import refuse a level without it, and `tests/solution-scenes.test.js` replays each shipped scene to `goal:reached` in CI — solvability is proven, not presumed (ADR 0009).
- **Solution capture** — how a level earns its solution scene: the sandbox editor stores each play-start snapshot (`run:started`) and stamps it as the capture when the loaded goal is actually won (`goal:reached`); the next Save writes it as `solution.scene`. Voided by a level load (another level's proof is not this one's) or a goal-type change. The fail overlay's Show-me-the-solution and the transport Give Up never grant completion credit — the SOLUTION posture cannot reach the goal checker.
- **Draft save** — a Save Level without a capture: `solution: null`, explained in the panel's solution notice. Player import and the campaign loader refuse it. The sandbox editor's Load opens it for repair (lenient by design), so the authoring loop is save-draft → Load → win a Test run → Save the proof.
- **Give up** — the player posture switch to the SOLUTION view: player postures only (fail overlay's Show-me-the-solution button, or the 🏳 transport control), the board swapped to the level's solution scene. Read-only: no drag, no palette, the loop not stepped and no physics bodies added.
- **SOLUTION posture** — the read-only display stage for a level's solution scene; header says what is shown. Return (the give-up control relabeled ↩, or Reset) rebuilds the level and restores the user's attempt — no completion credit ever flows from it.
- **Attempt snapshot** — the user's board, serialized at give-up time; the return path rebuilds the fixed furniture from level JSON and restores the player's parts from it (the same two-phase token bind a post-run reset uses).
## Player import (issue #70)

- **Player import** — "Import custom level" on the level-select screen opens a saved sandbox level AS A PLAYER: hide level select, `LevelManager.validateCustom` (deliberately the same `_validate` the campaign loader runs — a broken save is refused with a readable inline error, never partially built on the board), then `loadCustom` → `setMode(EDITING)` — the campaign solving posture, never the sandbox. The editor's own import stays lenient on purpose: it must open broken saves for repair.
- **Header goal line** — `#goal-name`, filled by `main.setHeaderLevel(levelData, placedObjects)` on every `level:loaded` (name + `goalSentence()`, no sandbox fallback: an unresolvable zone is said out loud, an imported unimplemented goal type says it cannot be won yet). Player sessions keep the line through EDITING/PLAYING/PAUSED/WON; entering the sandbox clears it (#63 posture — the editor readout is the goal truth there). Exported separately from the wiring for the same unit-testability as `wireSpeedControl`.
- **goalSentence** — the one plain-language builder (GoalChecker.js) behind both the editor's goal readout and the player header line: same resolver, same sentences — they cannot drift apart or promise a win the checker does not keep.
